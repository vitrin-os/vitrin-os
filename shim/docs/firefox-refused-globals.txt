# Interfaces Firefox 140.12.0esr asks for and the v0 global set DELIBERATELY
# does not provide (P1.6.4, issue #36).
#
# MACHINE-READABLE ON PURPOSE. The P1.6.4 acceptance script
# (tests/acceptance/firefox_bringup.sh, check D) runs the shim with
# --probe-globals and requires every `globals-demand` line to name an
# interface listed here. So this file is not a note, it is an ALLOWLIST OF
# THINGS ALREADY DECIDED: the day a new ESR wants something new, the check
# goes red and a human has to make a decision -- add the global to
# shim/src/globals.c citing the demand line, or add it here with the reason
# written up in firefox.md. Silencing it by editing this file without writing
# the reason defeats the whole mechanism.
#
# One interface per line. Blank lines and '#' comments ignored. The argument
# for each is in firefox.md, section "What Firefox asked for and did not get".
#
# NOT EVERY LINE IS A REFUSAL, despite the filename (which is load-bearing --
# the acceptance script reads this path). `zwp_tablet_manager_v2` is NOT YET
# SERVED: no tablet vocabulary exists on the wire, and the device set the
# input classes were measured against has no tablet -- which is evidence about
# one machine, not a property of the class. firefox.md keeps the two registers
# apart; a demand line here is "the shim does not provide it today", and only
# firefox.md says whether that is a decision or a not-yet.
#
# THREE ENTRIES LEFT THIS FILE IN WS-E.4.2 (issue #222), which is the
# mechanism working rather than an exception to it:
# `zwp_relative_pointer_manager_v1`, `zwp_pointer_gestures_v1` and
# `zwp_pointer_constraints_v1` were added to the v0 set in
# shim/src/globals.c, each citing the `globals-demand` line in the evidence
# log below, because protocol version 2 grew the wire messages that feed them.
# They are removed from here rather than left as stale entries: the check is
# one-directional (every demand must be listed), so leaving them would not
# have failed anything -- it would only have made this file claim a refusal
# that is no longer true.
#
# The third arrived one half-issue after the other two, and the delay is the
# point rather than an accident: relative motion and gestures are input
# CLASSES the core already had events for, so serving them was a replay. A
# pointer constraint is an ASK, and it could not be served until the wire grew
# the request/verdict pair (`vitrin_shim_session.pointer_constraint` and
# `pointer_constraint_state`) for the core to answer it with. Until then the
# global would have been a promise the shim could not keep, which is the
# half-serving this whole mechanism exists to prevent.
#
# A FOURTH ENTRY LEFT IN WS-E.4.4 (issue #306), on exactly that precedent and
# for the same structural reason: `zwp_idle_inhibit_manager_v1` is an ASK, not a
# class, so it could not be served until the wire grew a verb for the core to
# hear it on (`vitrin_shim_session.idle_inhibit`). It is now in the v0 set in
# shim/src/globals.c, citing the `globals-demand` line at
# globals-touched-firefox-140.12.0esr.log:158, and is removed from here rather
# than left as a stale entry claiming a refusal that is no longer true.
#
# Evidence: globals-touched-firefox-140.12.0esr.log
