# Architecture — crate/directory ↔ PRD map

This page is the R8 bus-factor artifact (PRD §9): it maps the repository's
actual crates, directories, and modules to the sections of
[`docs/PRD.md`](PRD.md) that motivate them, so a code review can cite design
intent instead of re-deriving it, and a new contributor can find "why does
this file exist" in one hop. It documents **what is built**, as of this PR;
for **what is planned**, see [`docs/plan/`](plan/), especially
[`01-phase-1-mvp.md`](plan/01-phase-1-mvp.md) (epics/tasks) and
[`00-roadmap.md`](plan/00-roadmap.md) (phase-level milestones).

Where this page and the code disagree, **the code wins** — this is a map,
not a spec. The protocol's own source of truth is
`protocol/vitrin-v0.xml` (see [CLAUDE.md](../CLAUDE.md)); this page does not
restate protocol semantics, only where each interface's implementation
lives.

## 1. Top-level layout

```
vitrin-os/
├── protocol/          # wire-protocol IDL (source of truth) + RELAX NG schema
├── docs/
│   ├── PRD.md         # PRD (Doc 1) + Technical Architecture (Doc 2) — canonical vision/design
│   ├── ARCHITECTURE.md  # this file
│   ├── protocol/      # prose, one page per interface, normative conventions in 00-conventions.md
│   ├── plan/          # phase/epic/task breakdown, decision log, roadmap
│   └── demo/          # demo screencast: recording plan + (once recorded) the published artifact
├── crates/            # the Cargo workspace — see §2 below
├── shim/              # the Wayland shim, C + wlroots, OUTSIDE the Cargo workspace — see §3
├── sdk/python/        # the Python agent SDK — see §4
├── examples/
│   ├── agent-demo/               # the Phase-1 goal-directed demo agent (also the M1.5 gate)
│   │   ├── run_demo.py           #   the agent; README.md is the normative receipt encoding
│   │   └── form.html             #   the nested venue's form (a data file, not a template)
│   ├── shell/                    # the switcher and launcher as an ORDINARY CLIENT — not a desktop shell
│   │   └── run_shell.py          #   line-oriented, host-side; README.md says why that is structural
│   ├── realm.toml                # realm config template + security commentary
│   └── principals.toml           # identity-registry template
├── packaging/         # what a DISTRIBUTOR installs on a host — see §5
│   └── apparmor/vitrind          # the Ubuntu 24.04+ userns grant (#286), UNPROVEN
└── tests/
    ├── integration/    # drives the SHIPPED vitrind BINARY over a real socket — see §5
    └── golden/         # reference frames + the golden-regeneration entrypoint (`cargo xtask bless`)
```

| [`vitrin-skip`](../crates/vitrin-skip) | Repo-wide test honesty, not a PRD section — issue [#288](https://github.com/vitrin-os/vitrin-os/issues/288) | **The sanctioned test skip.** `cargo test` captures stdout *and* stderr for tests that PASS, so every `eprintln!("SKIPPED: ...")` in this tree was invisible in CI: the `rust` job printed `993 passed` while exercising none of the confinement those tests cover. This crate replaces them with one machine-readable marker line and a **per-class require-variable** (`VITRIN_REQUIRE_CONFINEMENT`, `VITRIN_REQUIRE_LANDLOCK_ABI`, …) that turns a skip into a panic on a machine that declared it could run. The asymmetry is the design: a developer's kernel that cannot confine still skips; CI, which can, goes red. **The enforcement is a type, not a scan**: a capability probe returns an opaque `Verdict` with no accessor, no `Debug`, no `PartialEq` and no public field, so the answer cannot be learned without the marker being printed and the require-check applied — which is what makes "invert the guard and wrap the whole body" and "put the guard inside the measurement's own closure" stop compiling rather than merely get looked for. Its `Measured` token does the same for a measurement helper's closure. **What it does not close is enumerated in its own module docs** under "What this does NOT close"; the short version is that a test can still measure nothing without any of this noticing, and review is the only check on those shapes — a probe re-implemented inline instead of calling a sealed one, a local `macro_rules!` that expands to the early `return` a source scan reads for, an assertion sitting inside a conditional that is false at run time. That list is maintained in the crate, not here. Zero dependencies, Apache-2.0, never linked into `vitrind`. |

| `status/` (`mod.rs`, `render.rs`, `sample.rs`, `battery.rs`) | PRD §5.1 (the trusted path); WS-E.2.3 (issue #215) | The **status strip** (`--status`, off by default): the focused realm's name, the battery and a clock, drawn with the shared `paint/` rasterizer in reserved rows **immediately below the trusted band and never inside it**. | `chord.rs` | [D-024](plan/20-decision-log.md) (WS-E.2.1) | The **general modifier-aware chord matcher** the workstream shares: modifier state tracked from the keysyms `input/` already delivers, a physical-origin razor at both halves, and **exact** set-equality matching, so two chords over one trigger key can never both fire and no press can produce the wrong one. `deadman::Chord` excludes every modifier and `attention::AttentionChord` is nothing but modifiers, so neither can express `ctrl+shift+insert`; D-024 makes this the matcher WS-E.2.2 (#214) and WS-E.2.4 (#216) consume rather than each adding a parallel one to the stack the human's off-switch lives in. |
| `clipboard.rs` | PRD §11 (clipboard broker); [D-024](plan/20-decision-log.md) (WS-E.2.1) | The **cross-realm clipboard**: one core-held slot, `text/plain;charset=utf-8` only, capped at 61440 bytes (measured, and the wire's own ceiling), cleared on a timeout, on the source realm's death and by `deadman::apply`. **The core pulls** — filling the slot needs a `PendingPromotion` that only a human's promote chord mints, is neither `Copy` nor `Clone`, and is consumed by value, so an unsolicited `selection` from a compromised shim fills nothing. **The first place the TCB retains bytes an application authored**, which is an accepted cost rather than a mitigated one; `ClipboardContent`'s hand-written `Debug` prints a length and a digest, because a derived one on anything holding the slot would print a password into a panic message. |
| `screenshot.rs` | PRD §5.1 (the trusted path); [D-027](plan/20-decision-log.md) (WS-E.2.4) | The **human's screenshot key** (`--screenshot-dir`, off by default): a core-owned chord that writes one PNG of the focused realm's view and **touches no grant** — there is no facet, no verb and no principal in it, because a human photographing their own screen is not an agent capability. That is a type rather than a rule: `capture::render_screenshot` takes a `HumanGesture` with a private field and no constructor outside this module, minted only from a gesture the physical-origin chord matcher produced, and `enforcement.rs`'s source scan counts the identifiers in both directions. It reads the **realm view**, not human-visible output, so the trusted band's colour — the session secret — can never reach a file a same-uid app can open; the two softer designs (cropping the band, redacting by colour) are argued down in the module docs, the second because it hands the app an oracle. The path is not a string: the directory is audited and **held open** at startup, names are minted from two integers this module owns, and files are created `O_CREAT|O_EXCL|O_NOFOLLOW`, mode 600. Since [#240](https://github.com/vitrin-os/vitrin-os/issues/240) the encode runs on a **worker thread that owns that descriptor**, so the compositor thread pays one copy of the frame (4.2 ms at 2560x1600, measured) instead of the whole 71.7 ms encode. What that move buys is TOCTOU and symlink resistance for the write, **not** a smaller filesystem reach: `vitrind` is unsandboxed and single-uid, so no thread boundary stops any thread naming a path and creating a file under it ([#261](https://github.com/vitrin-os/vitrin-os/issues/261)). The published cost — a screenshot that cannot show a consent prompt — is in `docs/book/src/limits.md`. |
| `vt.rs` (`--features drm-backend`) | [D-031](plan/20-decision-log.md) (WS-E.3.5) | **The VT escape**: `Ctrl-Alt-F1`..`Ctrl-Alt-F12`, matched on physical input only, consumed in every realm, and turned into the one `Session::change_vt` call in the workspace. It exists because [D-030(1)](plan/20-decision-log.md) refused to implement the chord — correctly reasoning that a display server which traps the human on its own VT is hostile, and missing that **once a process holds DRM master the kernel stops handling `Ctrl-Alt-F<n>`**, so the refusal *was* the trap. That was observed, not deduced: the backend's first run on hardware (2026-08-09) left the repo owner unable to leave his own session. Unforgeable the `screenshot::HumanGesture` way — `VtRequest`'s constructor is private, its only producer is a physical-origin `chord::ChordMatcher` match, and the drain takes one by value — so "no principal can move the human's VT" is a compile error. It is the **first hook ever placed outside `lock::LockGate`**, because the escape must work while locked, and the collision refusal in `main` reserves `f1`..`f12` from every other core chord under `--drm`. |
| `notice.rs` | [D-031](plan/20-decision-log.md) (WS-E.3.5) | **The surface that can tell a trapped human something.** A bounded, expiring, human-visible-only band raised when a `change_vt` is refused, or accepted and never acknowledged — `libseat_switch_session` is asynchronous, so `Ok` means *accepted*, not *switched*. A log line is worth nothing to somebody who cannot leave the screen to read it, which is the original defect with an extra step. Closed vocabulary: `NoticeContent` has no `String` field, so the only glyphs are `const`s of this file plus core-chosen integers. Cannot reach the trusted band (it blits at `max(TRUST_BAND_HEIGHT, height - band_height)`, `status`'s discipline) and cannot reach a capture (its one call site is `backend::winit::window_pixels`, downstream of the output-stage fork) — which matters here specifically, because "this human's session is trapped" is exactly what an adversarial agent would most like to learn. |
| `cursor.rs` | PRD §20.15 / plan [D-019](plan/20-decision-log.md) (agent cursor drawing); Doc 2 §8's origin split | The agent cursor sprite: one geometry function (`agent_cursor_rects`) read by **both** human-visible presentation paths — the CPU composite and `dmabuf.rs`'s draw list — so they cannot paint different crosshairs, the way `trust_band_rect` already works for the band. Drawn from `input/`'s **agent-owned** position (`InputRouter::agent_pointer`, emulated origin only), never the shared one both origins write, and clipped below the trusted band because an agent picks its own coordinates. **Drawing only:** seat delivery to the shim is still one shared pointer position per realm view — D-017's per-principal *delivery* deferral to M2 is untouched. Human-visible output only, at the same output stage as the consent overlay, so no capture can contain it; nested composites it whenever it is offered one, headless only under `--agent-cursor` (its human-visible framebuffer is measured against the realm view by `band_witness.rs`). **Since WS-E.1.3 it is not always offered**: `session::post_dispatch` passes a position only when the router's realm is the realm the output is bound to, because the sprite is drawn in the output's coordinates over the output's realm. So an agent actuating inside a hidden realm draws no crosshair and the human loses the signal for it entirely -- D-019 was amended rather than kept, and the cost is published in `docs/book/src/limits.md`. |
| `input/` | Doc 2 §8 (input pipeline); plan requirement B2 (physical-vs-emulated origin tagging); [D-028](plan/20-decision-log.md) (WS-E.3.1) | Input intake and the `origin` tag (`physical`/`emulated`) applied at the point of entry, carried through to every `vitrin_shim_seat` event — the structural hook later phases hang physically-originated consent on. `keymap.rs` is the core's own xkb state, and it is the **only** place a scancode becomes a letter: a nested core gets an already-interpreted `logical_key` and a headless one has no keyboard, so it is behind the off-by-default `session-keymap` feature and a default `vitrind` links no `libxkbcommon` at all (measurable with `readelf -d`). It compiles a keymap **file** the operator names, with no include path and no `XKB_*` environment, because layout-name resolution reads `~/.config/xkb` and a realm's app runs as the core's uid. D-028 also moved press/release pairing from the keysym to the **scancode**, and made a release carry the keysym its own press delivered — without that second half the shim would be told to release a keycode the app never held. |
| `session.rs` | Not a single PRD section — the runtime glue (plan P1.M1.1) | Binds the core socket, accepts principal connections, drives a `PrincipalServer` per connection against the shared capability kernel, services **each** realm's shim socketpair (keyed by realm id since WS-E.1.2, which is where the multi-realm re-plumbing actually landed), and sweeps expired petitions/grants. This is what makes every module above reachable from a running binary. |
| `recorder.rs` | Plan requirement B1 (replay-ready log entries); PRD Doc 2's journal concept, reduced to an MVP seed | The flight-recorder: a JSON-lines log of handshakes, grant lifecycle, consent decisions, and actuations, with per-capture observation digests. Explicitly **not** the signed journal of a later phase. |
| `toml_subset.rs` | Not a PRD section — a security-motivated implementation detail | The deliberately strict TOML dialect `realm.toml`/`principals.toml` are parsed with (comments, `[[table]]` headers, string/string-array values only) — every file it accepts is valid TOML, but it accepts much less than a general parser would, so a config file cannot smuggle in a construct nobody reviewed. |
| `test_pattern.rs` | PRD plan E3 (P1.3.1 acceptance: "shows the test pattern") | The deterministic synthetic image the scene renders before any client surface has committed — what the earliest golden tests assert against. |

wlroots without pulling a Rust wlroots binding into the loop; Meson-built).
Maps to Doc 2 §4 (shim architecture) and PRD plan E6 (P1.6).

| Path | PRD mapping | Role |
|---|---|---|
| `include/vitrin-protocol.h` | Doc 2 §3.2 (wire format) | Generated C header (marshal/unmarshal helpers) — never hand-edited; regenerate with `cargo xtask codegen`. |
| `src/main.c`, `src/server.c` | Doc 2 §4.1 (one binary, N instances, spawn model); §4.2 (Wayland shim) | The wlroots **headless** backend compositor: one instance, one private socket, one app — spawned by the core's `spawn.rs`, never touches real hardware (the core owns the screen). |
| `src/clipboard.c` | PRD §11; [D-024](plan/20-decision-log.md) (WS-E.2.1) | The shim half of the cross-realm clipboard: the `request_set_selection` listener that makes the app's *own* clipboard work at all, plus the two directions the **core** drives — read the app's selection through a pipe and answer `selection` exactly once (always, including `empty`), and install a core-supplied payload as the app's selection on `offer_selection`.
